# 食品寄递线索协同闭环

连接食品协议客户的**资质时态核验**、寄递企业的**揽件/转运事件**与邮政管理、
市场监管之间的**跨部门风险处置**。网点只负责发现与上报，是否核查、放行或
立案由市场监管独立决定；双方通过接口看到权限范围内的责任和完整交接时间线。

## 领域边界与角色

| 角色 | 能做 | 不能做 |
| --- | --- | --- |
| 快递网点人员 | 揽件验视、上报线索、暂停本企业**未发出**包裹、履行通知责任 | 判违法、放行/立案、关闭线索、暂停已发出件 |
| 邮政管理人员 | 跨部门移交、协调、风险扩大申请、回执催办见证 | 替监管作出放行/立案决定 |
| 市场监管人员 | 受理核查、放行、不予处置、立案、解除冻结、签收移交 | —— |
| 食品协议客户 | 查看自身包裹物流事实与投诉 | 查看线索处置细节、处置包裹 |

**职责硬约束**：原上报人不能关闭自己上报的线索（`clues.close` 显式拒绝），
处置决定只接受市场监管角色。

## 核心机制

### 1. 全部档案按生效区间（bi-temporal effective range）

`temporal.py` 中资质（`Qualification`）、经营场所（`Premise`）、外设仓库
（`Warehouse`）、专属核验码（`VerificationCode`）都是不可变版本，
用半开区间 `[valid_from, valid_to)` 表示有效期：

- 查询一律 `as_of(时刻)`，取**当时生效**版本；换证、迁址、换码不回写历史；
- 新版本区间与旧版本重叠会被拒绝，相邻版本无缝衔接；
- 首次揽件时核验码当版地址与现场仓库比对，现场地址等于码面地址或属于
  当时生效的经营场所/外设仓库才算一致。

### 2. 揽件验视只存“当时所见”，流水幂等

`pickup.py` 的 `InspectionSnapshot` 只冻结：证照摘要（证号、范围、证面
有效期、原件指纹，不留影像）、货物类别、温控条件、位置、包装所见。

- 网点流水 `serial` 是幂等键：离线重传**同文** → 返回原揽件（`REPLAYED`），
  绝不生成第二次揽件；
- **同流水异文** → 两次内容都保留，异文进入隔离区
  （`QuarantineEntry`），原揽件不动。

### 3. 线索按各自规则版本分级

`rules.py` 中地址不符、证照过期、包装异常、温控中断是四条**独立发布**的
规则版本链。揽件当时适用哪个版本就按哪个版本定级（`ClueLevel`），
温控中断还可按中断时长分档；规则升级不溯及既往，历史线索永久保留其
`rule_version` 与级别。

### 4. 企业暂停 vs 监管冻结/放行（互斥且原子）

`parcels.py` 的包裹状态机：

```
PICKED_UP ⇄ PAUSED        # 仅未发出件，企业可暂停/恢复
PICKED_UP → DISPATCHED → IN_TRANSIT → DELIVERED   # 妥投为不可变终态事实
任一非终态 → FROZEN →（监管放行）回到冻结前状态
IN_TRANSIT → RETURNING → RETURNED
```

- 状态迁移带单调 `status_seq`，全部走 CAS（`require_seq`）；
- 冻结中的扫描一律拒绝；旧决定携带过期序号提交时直接 `ConflictError`，
  **不会出现放行与冻结并存，也不会让旧决定覆盖新扫描状态**；
- `release_freeze` 先做 CAS 校验再改字段，失败不留“无主冻结”。

### 5. 风险扩大只波及实际关联件，妥投转通知责任

`propagate_batch(batch_id)`：同一线索批次内——

- 在途/未发出且未终态的实际关联件 → 冻结；
- **已妥投件状态绝不回改**，生成 `NotificationDuty`（通知/召回责任），
  由企业履行；
- 已退回等终态件、不属于该批次的件一律不受影响。

### 6. 跨部门移交与完整交接时间线

`handoff.py` 每次移交产生只增的 `Handoff` 与时间线 `TimelineEntry`：
发起/接收组织、线索与包裹范围、回执期限、签收事实、催办次数都在其中。
时间线按组织可见性过滤：交接双方看到完整交接链条，客户只见自身物流事实。

### 7. 重启后继续：温控时限、待核查、回执催办

`scheduler.py` 管理三类可持久化事项，服务 `tick(now)` 推进：

- `TEMP_DEADLINE`：冷链中断到点未恢复 → 按当时规则版本升级线索，恢复即撤销；
- `REVIEW_DUE`：监管核查承诺到期提醒；
- `RECEIPT_REMINDER`：移交回执逾期周期催办，签收即停。

`store.py` 用带类型标签的 JSON 做原子快照（临时文件 + `os.replace`），
`CoordinationService.save/load` 整体恢复；重启后重新 `tick`，未竟事项继续。

后续转运、退回、投诉通过正确链路锚点归位（`complaints.py` 的
`serial / tracking_no / clue_id` 三选一，锚点不存在不受理），投诉办结
不产生包裹处置权、也不能关闭线索。

## 代码结构

```
src/food_parcel_regulation/
  errors.py       领域错误（权限、冲突、幂等冲突、规则等）
  timeutils.py    业务时钟与半开区间工具
  actors.py       角色、组织与权限
  temporal.py     资质/场所/仓库/核验码的生效区间版本
  pickup.py       验视快照、流水幂等、异文隔离
  rules.py        四类异常的规则版本与分级
  clues.py        线索生命周期（上报→核查→放行/立案/移交）
  parcels.py      包裹状态机、冻结/放行 CAS、风险传播、通知责任
  complaints.py   投诉归入正确链路
  handoff.py      跨部门交接、回执、只增交接时间线
  scheduler.py    温控时限/待核查/回执催办（可持久化）
  store.py        类型感知 JSON 快照与重启恢复
  service.py      CoordinationService 门面，编排上述全部模块
  context.py      读取领域资料（domain.json）
```
